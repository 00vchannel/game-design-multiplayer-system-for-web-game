# 驗證情境
依當次使用者與專案授權執行，不把未執行寫成通過。雙分頁不是兩地網路；模擬手機不是實體手機。

1. 安裝與建置：鎖定版本依賴、npm test、npm run build、Wrangler dry-run。前端與房間服務都啟動後再開房。
2. 兩人起步：房主開房、複製邀請、第二個獨立瀏覽器加入，看到相同名單；一人不可開始，兩人才能開始。
3. 四人與拒絕：最多四人，第五人明確拒絕；無效 invite、不同協定版本拒絕；局中加入回覆等待下一局。
4. 共同狀態：兩邊同時操作，位置、分數、物品與勝負一致。對同一物品連按／同時領取，不能生成兩份；重複 seq 不可重複計分。
5. 背景：房主切分頁／切軟體超過 20 秒，客人仍可操作；返回不誤關房。若測試工具只是模擬 visibility 事件，必須標明。
6. 凍結：暫停房主執行後恢復，不瞬間補算幾分鐘、不因舊心跳誤判；完全斷網與真正關閉房主應結束，不能殘留假房間。
7. 離開：客人拿物品後離線，物品回到可取得位置；房主真的離開時全員收到結束提示。
8. 再開一局：同房再開局 round 增加；分數、倒數、物品、輸入、cooldown、seq 重設。延遲舊 round 快照不得污染新局。
9. 手機：觸控移動＋互動，手指移出、取消觸控、切背景後釋放方向；名稱與連結不撐破 390px 寬度。
10. 公開驗證（取得發佈授權後）：正式 HTTPS 邀請、兩種網路上的電腦與手機。免費額度失敗要顯示錯誤，不開付費服務。

範本的自動單元檢查只驗證協定與示例玩法；不代表修改後的使用者遊戲已通過以上各項。修改 adapter 的結構後，補與該玩法相關的爭用、離線回收及重開局檢查。
